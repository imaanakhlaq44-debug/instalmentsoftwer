# Voice over — اردو

The guide video's narration, for recording by voice rather than by an engine.
English technical words are left in English on purpose: *layer*, *check-in*,
*agreement*, *dashboard*, *lock*, *IMEI* are the words a mobile counter in
Pakistan actually says, and the Urdu equivalents are not understood.

**One mp3 per numbered paragraph**, named `01.mp3`, `02.mp3` … inside a folder
per part (`p1`, `p2`, …). `docs/video/narration/README.md` has the details.
The numbering must not change: every shot in `scripts/video/build.mjs` is tied
to the paragraph it illustrates, and that is what keeps the picture with the
voice.

## حصہ ۲ — لاک، سیل، QR، معاہدہ

**1.**
اب lock کی بات۔ ہمارا حساب monthly fee کا نہیں ہے: آپ locks ‏packs میں خریدتے ہیں، اور ایک lock ایک فون پر خرچ ہوتا ہے۔ فون enroll ہوا، lock خرچ ہوا۔ قسطیں پوری ہونے کے بعد بھی وہ lock واپس نہیں آتا — اسی لیے سستا پڑتا ہے، کیونکہ آپ ہر مہینے کچھ نہیں دیتے۔

**2.**
اب sale۔ پہلے یہ کام تین screens پر ہوتا تھا — گاہک، فون، plan۔ اب سب ایک ہی page پر ہے۔

**3.**
پرانا گاہک ہے؟ صرف CNIC نمبر ڈالیے — نام، نمبر، پتہ خود بھر جاتا ہے۔ دوبارہ لکھنے کی ضرورت نہیں۔

**4.**
اور IMEI۔ اب ہاتھ سے لکھنے کی ضرورت نہیں: یہ Scan کا button دبائیے، فون کا camera ڈبے کے IMEI پر رکھیے، digits خود بھر جاتے ہیں۔ ایک digit غلط لکھنے کا خطرہ ختم — اور یہ خطرہ بڑا ہے، کیونکہ پورا lock اسی IMEI پر کھڑا ہوتا ہے۔

**5.**
پھر plan: قیمت، advance، کتنے مہینے۔ Schedule خود بن جاتا ہے، اور حساب آخری قسط میں پورا برابر ہوتا ہے — ایک روپے کا فرق بھی نہیں۔

**6.**
اب فون جوڑنا۔ Sale کے بعد ایک QR code بنتا ہے۔ نیا یا reset کیا ہوا Android فون — پہلی screen پر چھے دفعہ tap کیجیے، camera کھلتا ہے، QR ‏scan کیجیے۔ ہماری app ‏device owner بن کر install ہوتی ہے۔

**7.**
یہ QR ایک ہی دفعہ چلتا ہے۔ دو بندوں نے ایک ساتھ scan کیا تو صرف ایک کامیاب ہوگا، دوسرے کو صاف جواب ملے گا۔

**8.**
اور اب وہ حصہ جو قانونی طور پر سب سے ضروری ہے: agreement۔

**9.**
Sale کے ساتھ ہی agreement بن جاتا ہے — اردو اور English دونوں میں، اسی plan کے اصل حساب کے ساتھ۔ گاہک وہیں، اسی screen پر، انگلی سے signature کرتا ہے۔ الگ page پر جانے کی ضرورت نہیں۔

**10.**
اور یہ صرف کاغذ نہیں ہے۔ جس فون پر signature نہیں، system اسے lock کرنے سے انکار کر دیتا ہے۔ اگر بعد میں plan کا حساب بدل گیا اور نیا signature نہیں ہوا، تو بھی انکار۔ Signed agreement کے بغیر کوئی فون lock نہیں ہوتا — نہ آپ کے ہاتھ سے، نہ ہمارے ہاتھ سے۔

## حصہ ۳ — IMEI، اور چار layers

**1.**
اب وہ سوال جو ہر دکاندار پوچھتا ہے، اور جس کا جواب اکثر کوئی نہیں دیتا: IMEI ‏change کرا لیا تو؟

**2.**
جواب ایک نہیں، چار ہیں۔ چار الگ layers۔ اور جو بندہ فون لے کر بھاگنا چاہتا ہے، اسے چاروں layers توڑنی پڑیں گی۔

**3.**
پہلی layer: lock ایک ہی IMEI پر۔

**4.**
جو IMEI آپ نے sale کے وقت register کیا، lock اسی پر خرچ ہوتا ہے۔ جب فون enroll ہوتا ہے، server اس کا بتایا ہوا IMEI ‏sale کے record سے match کرتا ہے۔

**5.**
Match نہیں ہوا؟ فون enroll ہی نہیں ہوتا۔ نہ lock لگتا ہے، نہ آپ کا licence خرچ ہوتا ہے — اور dashboard پر لکھا آتا ہے کہ کوشش روک دی گئی، کس فون پر اور کب۔ یعنی دوسرے فون پر آپ کا lock چلانا شروع سے ہی بند ہے۔

**6.**
دوسری layer: ہر پندرہ منٹ بعد دوبارہ check۔

**7.**
Enroll ہونے کے بعد بات ختم نہیں ہوتی۔ فون ہر پندرہ منٹ بعد اپنا IMEI، اپنا serial number اور اپنے hardware کی report بھیجتا ہے۔

**8.**
جس دن IMEI بدلا، server اسی check-in پر پکڑ لیتا ہے۔ دکاندار کو alert جاتا ہے — دیکھیے، یہاں، registered IMEI اور reported IMEI ساتھ ساتھ لکھے ہیں — اور فون خود بخود lock ہو جاتا ہے۔ کسی کے button دبانے کا انتظار نہیں۔

**9.**
تیسری layer، اور یہی سب سے مضبوط ہے: فون کا secure chip خود گواہی دیتا ہے۔

**10.**
Software کا IMEI بدل دینا ایک بات ہے۔ فون کے secure chip کو جھوٹ بلوانا بالکل دوسری بات ہے۔

**11.**
فون کا chip اپنے factory IMEI پر digital signature کرتا ہے — اسی challenge پر جو server نے خود چنا ہوتا ہے۔ پہلی دفعہ enrollment code سے بنا challenge، اس کے بعد روز نیا۔ پھر server اس signature کو Google کے root certificates سے verify کرتا ہے: signature اصلی ہے یا نہیں، chip اصلی ہے یا نہیں، certificate ‏revoke ہوا ہے یا نہیں۔

**12.**
Chip کا IMEI ‏registered IMEI سے match نہ ہوا — alert۔ Signature جعلی یا کٹا پھٹا — alert۔ یہ layer ہماری app پر بھروسہ نہیں کرتی؛ hardware پر کرتی ہے۔

**13.**
چوتھی layer: app ہٹانا اور reset کرنا، دونوں بند۔

**14.**
سوچ یہ ہوتی ہے کہ app ہٹا دیں گے یا factory reset مار دیں گے۔ دونوں بند ہیں۔ App ‏device owner ہوتی ہے — گاہک اسے uninstall نہیں کر سکتا، اور reset کی کوشش روک دی جاتی ہے۔

**15.**
اور اگر کسی طریقے سے فون wipe ہو جائے، Factory Reset Protection کی وجہ سے فون صرف دکان کے Google account سے چلتا ہے۔ چوری کا فون کسی اور کے کام کا نہیں رہتا۔

**16.**
اور ان تین چیزوں پر بھی نظر ہے: app نے device owner کھویا، bootloader کھلا، یا فون root ہوا — تینوں dashboard پر record ہوتے ہیں، اور انہی پر فون lock ہو جاتا ہے۔

**17.**
تو جواب یہ ہے: چار layers، اور ہر layer الگ جگہ پر پکڑتی ہے۔

**18.**
میں یہ نہیں کہوں گا کہ IMEI بدلنا ناممکن ہے — کوئی بھی سچ بولنے والا یہ نہیں کہے گا۔ میں یہ کہہ رہا ہوں کہ پکڑا جاتا ہے: enroll ہوتے وقت، ہر پندرہ منٹ والے check-in پر، chip کی گواہی پر، اور app ہٹانے کی کوشش پر۔

**19.**
اور ایک بات جو آپ کو ہر system میں نہیں ملے گی: یہ system آپ سے جھوٹ نہیں بولتا۔ جو فون lock نہیں ہو سکا، dashboard اسے "lock ہو گیا" نہیں دکھاتا — "lock نہیں ہوا" ہی دکھاتا ہے، صاف صاف۔ کیونکہ جھوٹا lock اس نقصان سے زیادہ خطرناک ہے جو آپ کو پتہ ہو۔
